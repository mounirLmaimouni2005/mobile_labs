# Lab Creator

Use this Skill to create, organize, review, or update the files and learning materials required for a technical lab.

## Workflow

### 1. Understand the Lab

1. Read the complete `README.md`.
2. Read all applicable rules from the workspace.
3. Identify relevant Skills and follow their instructions.
4. Inspect the existing project structure and files before making changes.
5. Understand the lab objectives, required topics, expected deliverables, and constraints.

### 2. Plan the Work

1. Identify exactly what the lab requires.
2. Follow the file structure and deliverables specified in the README.
3. Identify which files already exist and can be reused.
4. Determine the appropriate technologies, formats, and tools from the lab requirements.
5. Do not start creating files before understanding the requested structure.

### 3. Create or Update Lab Materials

1. Create only the files required by the README or explicitly requested by the user.
2. Keep the existing title, objectives, requirements, and useful content.
3. Organize the content in a clear and logical structure.
4. Adapt explanations, examples, and exercises to the learner's level.
5. Follow the language and formatting requirements defined by the README.
6. Use practical examples that are relevant to the lab topic.
7. Keep explanations clear, progressive, and focused on understanding.

### 4. Maintain Consistency

1. Ensure that all created files follow the same lab objectives and requirements.
2. Keep tutorials, examples, documentation, presentations, and practical exercises consistent with one another.
3. Make sure every example is explained where necessary.
4. Do not introduce concepts or requirements that conflict with the README.
5. Distinguish theoretical explanations from practical application.
6. Keep all documentation synchronized when requirements or files change.

### 5. Verify the Work

1. Check the accuracy of technical explanations and terminology.
2. Verify commands, configurations, and versions using available tools or reliable references when necessary.
3. Run relevant examples, commands, or tests when the required tools are available.
4. Report only checks that were actually performed.
5. Clearly identify anything that could not be verified.
6. Correct errors found during verification when within the scope of the task.

## Facts and Limitations

- Never invent project requirements, application details, architectures, technologies, packages, versions, configurations, or test results.
- Use the README and existing project files as the primary source of project-specific information.
- Do not assume that every lab requires tutorials, code examples, presentations, or integration notes.
- Do not impose a predefined file structure when the README already defines one.
- If essential information is missing, ask the user or clearly mark the missing information instead of inventing it.
- Clearly distinguish real project implementation from educational examples.
- Do not add unnecessary setup instructions, introductory examples, exercises, slides, files, folders, or dependencies.
- Preserve existing custom files and workspace conventions.
- Modify only what is necessary for the requested task.

## Final Quality Checklist

Before finishing, ensure that:

- [ ] The work follows the lab objectives and README requirements.
- [ ] All requested deliverables are present.
- [ ] The content is accurate and understandable.
- [ ] Examples and documentation are consistent.
- [ ] Relevant checks have been performed when possible.
- [ ] No unnecessary files or dependencies were introduced.
- [ ] All modifications are limited to the requested scope.
