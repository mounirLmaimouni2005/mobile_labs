# General Workspace Rules

## 1. Context and Instructions

- Before starting a task, read the relevant `README.md`.
- Read applicable rules from `.agent/rules/`.
- Identify and use relevant skills from `.agent/skills/`.
- Follow the existing workspace structure and conventions.
- Do not assume instructions from another lab apply to the current lab.

## 2. Accuracy and Learning

- Write for the learner's current level.
- Explain concepts clearly and progressively.
- Use reliable and relevant references when needed.
- Never invent project information, requirements, tools, versions, test results, or completed work.
- Clearly distinguish verified facts from assumptions and examples.

## 3. Workspace Management

- Inspect the existing project structure before making changes.
- Reuse existing files and resources when appropriate.
- Modify only files required by the current task.
- Do not create unnecessary files, folders, or dependencies.
- Preserve existing project conventions unless the task requires a change.

## 4. Quality Control

- Verify the accuracy and completeness of the requested work.
- Run relevant checks when the required tools are available.
- Report actual verification results honestly.
- Never claim that a command, test, or validation succeeded if it was not executed.

## 5. Final Response

- Summarize the work completed.
- Mention important files created or modified.
- Clearly report any checks that were performed and their results.
- At the end of the final response, name only the skills actually used for the task.
- Do not list skills that were merely available.
