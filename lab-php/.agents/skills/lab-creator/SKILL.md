# Lab Creator

Use this Skill to make lab files from the README and current project rules.

## Steps

1. Read the full README, useful rules, and useful Skills. Read files before you change them.
2. Keep the current title, goal, and useful content. For this PHP Lab, keep the three README parts: "Project technical need", "Topics and skills to learn", and "Expected work".
3. Use the file list in the README. For this PHP Lab, make one tutorial in `tutorials/` for each topic, one matching PHP example in `examples/`, a Marp deck in `presentation.md`, and notes in `docs/integration-notes.md`. Explain the files in the README.
4. Write in English and use words for new learners. Each tutorial needs the meaning, use, main code, example, good ways to work, common mistakes, run command, result, and an exercise.
5. Keep all files in line. Each tutorial must explain its example. Slides must show the same topics and results. Notes must show what is known and what is only an idea.
6. Check commands and versions with the tools that are ready. Run each example when possible. Write only real checks and results.

## Facts and limits

- Do not make up an app, its design, packages, file loader, real problem, minimum PHP version, or test result.
- Say when examples are only for learning and do not belong to an app.
- If a task needs a real problem from the learner and no problem is given, leave a clear place to fill in. Do not make one up.
- Do not add files, folders, or packages outside the requested list. Keep current custom files.
- Do not add setup steps, a Hello World example, or extra slides unless they are needed.
